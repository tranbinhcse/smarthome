# hubd — Kế hoạch triển khai

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Mục tiêu:** Xây `hubd`, phần mềm trung tâm đóng thành một file binary. `hubd` làm 5 việc:
- nhận dữ liệu từ các node qua MQTT;
- lưu lịch sử vào SQLite;
- chạy luật tự động hoá;
- phục vụ giao diện web cho màn hình Surface và điện thoại;
- gửi cảnh báo Telegram.

**Kiến trúc:**
- Một package `main` gồm nhiều file nhỏ, mỗi file một trách nhiệm.
- Mọi trạng thái (store, rules engine, thiết bị) do **một goroutine vòng lặp** sở hữu. MQTT callback, ticker và HTTP handler gửi hàm vào vòng lặp qua channel, nên không cần mutex cho trạng thái.
- SQLite (WAL) dùng chung một file cho lịch sử, hàng đợi Telegram và token đăng nhập.

**Tech stack:**
- Go ≥ 1.24.
- `gopkg.in/yaml.v3`, `modernc.org/sqlite`, `github.com/eclipse/paho.mqtt.golang`.
- uPlot nhúng sẵn trong binary.
- Mosquitto chạy riêng: Homebrew khi dev trên Mac, apt trên trung tâm (Surface Pro 5, Debian).

**Spec:** `docs/2026-10-26-trung-tam-dieu-khien-nha-design.md`, mục 7, 9, 10, 11 và tiêu chí Giai đoạn 1/6.

**Không thuộc plan này** (mỗi mục một plan riêng, viết sau Giai đoạn 0):
- OS và kiosk cho Surface Pro 5 (trung tâm kiêm màn hình);
- firmware ESPHome của các node;
- module Tuya local. Chỉ viết nếu khảo sát cho thấy có thiết bị không flash được, và khi đó đã biết phiên bản giao thức;
- camera Hikvision: `go2rtc`, `hikbridge`, trang Camera (spec mục 15.1);
- trợ lý giọng nói `voiced` (spec mục 15.2). Plan này chỉ lo phần `hubd` publish `hubd/alert`.

**Thư mục làm việc:** repo mới `hubd/`. Chủ nhà chọn vị trí khi bắt đầu thực thi. Mọi đường dẫn bên dưới tính từ gốc repo.

## Global Constraints

**Build và phụ thuộc**
- Build ra một binary tĩnh duy nhất: `CGO_ENABLED=0 GOOS=linux GOARCH=amd64` cho Surface Pro 5. Chuyển sang Pi 5 thì chỉ đổi thành `GOARCH=arm64`, không sửa code.
- Chỉ được dùng 3 thư viện Go bên ngoài: `gopkg.in/yaml.v3`, `modernc.org/sqlite`, `github.com/eclipse/paho.mqtt.golang`. Mọi thứ khác dùng thư viện chuẩn: web dùng `net/http` (route pattern của Go 1.22), dữ liệu tức thời dùng SSE.

**Cấu hình**
- Cấu hình nằm ở hai file `config.yaml` và `rules.yaml`, decode **strict** (`KnownFields(true)`): gõ sai tên trường là báo lỗi.
- Thêm thiết bị mới chỉ cần sửa cấu hình, không sửa code.
- Đường dẫn `*_file` (secrets) tính tương đối theo thư mục chứa `config.yaml`.
- `systemctl reload hubd` (SIGHUP) nạp lại cấu hình. **Cấu hình mới sai thì giữ cấu hình cũ** và ghi log `reload rejected: <lỗi>`.

**Lịch sử**
- Dữ liệu thô giữ **30 ngày**.
- Trung bình **5 phút** (bucket 300 s) giữ **730 ngày**.

**Cảnh báo**
- Mọi cảnh báo đồng thời được publish lên MQTT topic `hubd/alert`, payload `{"level":"...","text":"..."}`, cho các phần mở rộng (giọng nói, loa) dùng.
- Ba mức `urgent` | `warn` | `info`.
- `urgent` lặp lại **mỗi 1 phút** đến khi có người xác nhận.
- Mất mạng thì xếp hàng, có mạng thì gửi bù theo đúng thứ tự.

**Thiết bị và luật**
- `hubd` chỉ so ngưỡng. Giá trị dẫn xuất (PV dư = PV − tải, chênh lệch cell) do firmware ESPHome tính bằng template sensor rồi gửi lên như entity thường.
- Thiết bị `protected: true`: luật chỉ được đặt về `on`. Ràng buộc này kiểm hai lớp: khi validate cấu hình, và lúc chạy trong `SetDevice`.
- Lệnh từ người dùng tới thiết bị `pin: true` hoặc `protected: true` cần PIN.
- Tắt còi / xác nhận báo động không cần PIN.
- Entity mặc định mất hạn sau **10 phút** (`offline_after`). `offline_after: 0` nghĩa là không bao giờ mất hạn.

**Bảo mật**
- Sai PIN **5 lần** thì khoá **5 phút**.
- Cookie `hubd_token`: HttpOnly, SameSite=Strict, Path `/`, Max-Age 315360000.
- Body JSON của mọi request giới hạn 4 KB (`http.MaxBytesReader`).

**Giao diện**
- Không gọi CDN hay bất kỳ host ngoài nào.
- Nút bấm ≥ 48 px, nhãn tiếng Việt.

**Triển khai**
- Binary đặt ở `/data/bin/hubd`, vì root trên trung tâm chỉ đọc. Bản trước giữ ở `/data/bin/hubd.prev`.
- Commit theo conventional commits.

## Review Focus

1. **ESPHome gửi `nan` khi cảm biến hỏng.** Giá trị này không được kích hoạt hay xoá luật số, và không ghi vào lịch sử. Test: Task 2 `TestParsePayload`, Task 3 `TestNonNumericIsUnknown`, Task 6 `TestHubSkipsNaNInHistory`.
2. **Cảm biến mất hạn hoặc mất kết nối khi luật đang chờ hoặc đang kích hoạt.** Luật đang kích hoạt thì giữ nguyên, không chạy `on_clear`. Luật đang chờ thì đặt lại thời gian chờ. Entity trạng thái node phải để `offline_after: 0`, nếu không luật "node mất kết nối" sẽ không bao giờ kích hoạt. Test: Task 3 `TestUnknownHolds`.
3. **Mất internet nhiều giờ.** Telegram không được dồn hàng trăm tin `urgent`: mỗi báo động chỉ có tối đa 1 tin chờ gửi. Có mạng lại thì gửi đúng thứ tự. Test: Task 5 `TestUrgentRepeatsWithoutFlooding`, `TestNotifierQueuesWhileOffline`.
4. **Có người dò PIN trong mạng LAN.** Chặn bằng khoá 5 lần / 5 phút. Gọi API thiếu cookie thì trả 401. Test: Task 7 `TestPairWrongPINLockout`, `TestStateNeedsToken`.
5. **Mosquitto khởi động lại.** `hubd` phải subscribe lại, nên dùng OnConnect của paho chứ không subscribe một lần. Khi `hubd` khởi động lại, trạng thái được nạp lại từ các message retained. Kiểm ở Task 9, bước nghiệm thu 4.

```go
type Config struct {
	MQTT struct {
		Broker       string `yaml:"broker"`
		Username     string `yaml:"username"`
		PasswordFile string `yaml:"password_file"`
		Password     string `yaml:"-"`
	} `yaml:"mqtt"`
	HTTP struct {
		Listen  string `yaml:"listen"`
		PinFile string `yaml:"pin_file"`
		PIN     string `yaml:"-"`
	} `yaml:"http"`
	DataDir  string `yaml:"data_dir"`
	Telegram struct {
		APIBase   string `yaml:"api_base"` // mặc định https://api.telegram.org
		TokenFile string `yaml:"token_file"` // rỗng = chỉ ghi log
		ChatID    string `yaml:"chat_id"`
		Token     string `yaml:"-"`
	} `yaml:"telegram"`
	Alarm struct {
		Siren string `yaml:"siren"` // device id, tuỳ chọn
	} `yaml:"alarm"`
	Zones     []Zone    `yaml:"zones"`
	Entities  []Entity  `yaml:"entities"`
	Devices   []Device  `yaml:"devices"`
	Scenes    []Scene   `yaml:"scenes"`
	Dashboard Dashboard `yaml:"dashboard"`
	Rules     []Rule    `yaml:"-"` // nạp từ rules.yaml
}
type Zone struct{ ID, Name string }
type Entity struct {
	ID, Name, Zone, Unit, Topic string
	JSON         string         `yaml:"json"` // lấy một khoá từ payload JSON (Zigbee2MQTT)
	OfflineAfter *time.Duration `yaml:"offline_after"` // nil = 10m, 0 = không bao giờ
}
type Device struct {
	ID, Name, Zone, Panel string
	CommandTopic string            `yaml:"command_topic"`
	StateEntity  string            `yaml:"state_entity"`
	Payloads     map[string]string `yaml:"payloads"` // nil = {on: ON, off: OFF}
	Pin          bool              `yaml:"pin"`
	Protected    bool              `yaml:"protected"`
}
type Scene struct {
	ID, Name string
	Pin bool     `yaml:"pin"`
	Do  []Action `yaml:"do"`
}
type Dashboard struct {
	Overview []string `yaml:"overview"`
	Energy   struct {
		PV, Load, Grid, Battery, SOC string
		CellsPrefix string   `yaml:"cells_prefix"`
		Charts      []string `yaml:"charts"`
	} `yaml:"energy"`
}
type Rule struct {
	ID      string   `yaml:"id"`
	Between []string `yaml:"between"` // ["HH:MM","HH:MM"], được phép vắt qua nửa đêm
	When    Cond     `yaml:"when"`
	Then    []Action `yaml:"then"`
	OnClear []Action `yaml:"on_clear"`
}
type Cond struct {
	Entity     string        `yaml:"entity"`
	Above      *float64      `yaml:"above"`
	Below      *float64      `yaml:"below"`
	Is         string        `yaml:"is"` // "on" | "off"
	ClearBelow *float64      `yaml:"clear_below"`
	ClearAbove *float64      `yaml:"clear_above"`
	For        time.Duration `yaml:"for"`
	And        []Cond        `yaml:"and"` // so tức thời, không có hysteresis và không có for
}
type Action struct {
	Set    string `yaml:"set"`
	To     string `yaml:"to"`
	Notify string `yaml:"notify"`
	Level  string `yaml:"level"` // urgent|warn|info, rỗng = info
	Scene  string `yaml:"scene"`
	Rule   string `yaml:"-"` // engine điền id luật nguồn
}
```

Struct không có tag yaml dùng tên trường viết thường (`id`, `name`, `zone`, `unit`, `topic`, `panel`, `pv`, `load`, `grid`, `battery`, `soc`). Đặt tag tường minh cho các trường này để decode strict không bị lệch tên.

```go
func loadTestConfig(t *testing.T) *Config {
	t.Helper()
	cfg, err := LoadConfig("testdata/config.yaml", "testdata/rules.yaml")
	if err != nil {
		t.Fatal(err)
	}
	return cfg
}

func TestLoadConfigOK(t *testing.T) {
	cfg := loadTestConfig(t)
	if cfg.HTTP.PIN != "2468" {
		t.Fatalf("PIN = %q", cfg.HTTP.PIN)
	}
	if len(cfg.Rules) != 5 || cfg.Rules[0].When.For != 2*time.Minute {
		t.Fatalf("rules = %+v", cfg.Rules)
	}
	if cfg.Rules[0].Then[0].To != "on" || cfg.Rules[2].When.Is != "on" {
		t.Fatal("chữ on/off không đặt trong ngoặc kép phải giữ nguyên là chuỗi")
	}
	if cfg.Entity("node-pk.status").MaxAge() != 0 || cfg.Entity("phongkhach.co2").MaxAge() != 10*time.Minute {
		t.Fatal("offline_after: 0 = không bao giờ, mặc định = 10m")
	}
	if p, _ := cfg.Device("man_hinh_pk").Payload("dim"); p != "40" {
		t.Fatalf("dim = %q", p)
	}
	if got := cfg.Topics(); len(got) != 6 {
		t.Fatalf("topics = %v", got)
	}
}

func TestDefaultPayloads(t *testing.T) {
	d := Device{ID: "x"}
	if p, ok := d.Payload("on"); !ok || p != "ON" {
		t.Fatalf("on = %q", p)
	}
	if _, ok := d.Payload("dim"); ok {
		t.Fatal("mặc định không có dim")
	}
}

func TestValidateErrors(t *testing.T) {
	cases := []struct {
		name   string
		mutate func(c *Config)
		want   string
	}{
		{"dup id", func(c *Config) { c.Entities = append(c.Entities, c.Entities[0]) }, "duplicate id"},
		{"unknown zone", func(c *Config) { c.Entities[0].Zone = "xx" }, "unknown zone"},
		{"rule unknown entity", func(c *Config) { c.Rules[0].When.Entity = "xx" }, "unknown entity"},
		{"unknown device", func(c *Config) { c.Rules[0].Then[0].Set = "xx" }, "unknown device"},
		{"unknown state", func(c *Config) { c.Rules[0].Then[0].To = "blink" }, "unknown state"},
		{"no comparator", func(c *Config) { c.Rules[0].When.Above = nil }, "exactly one of above/below/is"},
		{"two comparators", func(c *Config) { c.Rules[0].When.Is = "on" }, "exactly one of above/below/is"},
		{"clear_below >= above", func(c *Config) { c.Rules[0].When.ClearBelow = f64(1100) }, "clear_below"},
		{"bad between", func(c *Config) { c.Rules[4].Between = []string{"25:00", "06:00"} }, "between"},
		{"rule turns protected off", func(c *Config) { c.Rules[0].Then[0] = Action{Set: "cb_tulanh", To: "off"} }, "protected"},
		{"scene needs pin", func(c *Config) { c.Scenes[0].Do[0].Set = "cb_nonglanh" }, "scene needs pin"},
		{"bad level", func(c *Config) { c.Rules[1].Then[1].Level = "loud" }, "level"},
		{"unknown scene", func(c *Config) { c.Rules[0].Then[0] = Action{Scene: "xx"} }, "unknown scene"},
	}
	for _, tc := range cases {
		t.Run(tc.name, func(t *testing.T) {
			cfg := loadTestConfig(t)
			tc.mutate(cfg)
			if err := cfg.Validate(); err == nil || !strings.Contains(err.Error(), tc.want) {
				t.Fatalf("err = %v, want %q", err, tc.want)
			}
		})
	}
}

func TestUnknownFieldRejected(t *testing.T) {

	if _, err := LoadConfig(c, r); err == nil || !strings.Contains(err.Error(), "entites") {
		t.Fatalf("err = %v", err)
	}
}
```

  1. Decode hai file bằng `yaml.NewDecoder` + `KnownFields(true)`.

  - mỗi action có đúng một trong `set`+`to` / `notify` / `scene`;
  - `to` phải là khoá có trong `Payload`;
  - `level` hợp lệ;
  - luật không được đặt thiết bị `protected` về giá trị khác `on`, kể cả gián tiếp qua scene mà luật gọi;

  - `alarm.siren` nếu có phải là device có trạng thái `off`.

**Ngữ nghĩa** (code phải làm đúng như sau):

- **Giá trị của điều kiện chính:**
  - `above X`:
    - chưa kích hoạt: đúng khi v > X;
    - đang kích hoạt: còn đúng khi v ≥ `clear_below`, hoặc v > X nếu không có `clear_below`.
  - `below X`: đối xứng với `above`, dùng `clear_above`.
  - `is on` / `is off`: v == 1 / v == 0.
- **Không xác định:** entity thiếu, mất hạn, hoặc `!IsNum`.
- **`and`:** mọi điều kiện con so tức thời. Có điều kiện con không xác định thì cả cụm không xác định.
- **Ngoài khung `between`:** coi như điều kiện sai (đã xác định).
- **Chuyển trạng thái:**

| Điều kiện | Luật đang | Kết quả |
|---|---|---|
| không xác định | đang chờ | xoá `pendingSince` |
| không xác định | đang kích hoạt | giữ nguyên, không phát action nào |
| đúng | chưa kích hoạt | đặt `pendingSince` nếu chưa có. Khi `now - pendingSince ≥ for`: kích hoạt và phát `Then` (`for` = 0 thì phát ngay) |
| sai | bất kỳ | xoá `pendingSince`. Nếu đang kích hoạt: tắt kích hoạt và phát `OnClear` |

```go
	Zones     []Zone       `json:"zones"`
	Entities  []EntityView `json:"entities"`
	Devices   []DeviceView `json:"devices"`
	Scenes    []SceneView  `json:"scenes"`

}

	Stale bool     `json:"stale"`
}
type DeviceView struct {

}
```

**Định dạng sự kiện gửi lên `Events()`** (JSON một dòng):
- `{"type":"entity","id":..,"value":..,"text":..,"at":..}`
- `{"type":"device","id":..,"state":..}`
- `{"type":"alarm","texts":[..]}`: chỉ gửi khi danh sách urgent thay đổi

**Hành vi:**
- **`OnMessage`:** với mỗi entity có topic khớp:
  1. `ParsePayload`; parse không được thì bỏ qua.
  2. Gán `At = now`, ghi vào store.
  3. Nếu `IsNum` thì `hist.Add`.
  4. Gửi sự kiện entity.

  Sau đó `Eval` engine và chạy các action.
- **Chạy action:**
  - `Set` → `SetDevice(.., byRule=true)`. Gặp `ErrProtected` thì ghi log và gửi `Notify(key=rule, "warn", "Đã chặn luật <rule> tắt <tên thiết bị>")`.
  - `Notify` → `notif.Notify(now, a.Rule, level, text)`, rồi `pub("hubd/alert", json)` với `json` là `{"level":"<level>","text":"<text>"}` (dùng `json.Marshal`, level rỗng ghi thành `info`).
  - `Scene` → chạy từng action trong scene với `byRule=true`.
- **`SetDevice`** kiểm theo thứ tự:
  1. device không tồn tại → `ErrUnknownDevice`;
  2. `to` không có payload → `ErrBadState`;
  3. `byRule && Protected && to != "on"` → `ErrProtected`.

  Qua hết thì `pub(command_topic, payload)`, ghi trạng thái đã ra lệnh, gửi sự kiện device.
- **`DeviceView.State`:** lấy `Text` của `state_entity` nếu có, ngược lại là lệnh gần nhất.

- Create: `main.go`, `mqtt.go`, `mqtt_integration_test.go`, `deploy/hubd.service`, `deploy/deploy.sh`

**Interfaces:**
- Consumes: mọi thứ từ Task 1–8.
- Produces:
  - Binary `hubd` với cờ `-config` (mặc định `/data/config.yaml`) và `-rules` (mặc định `/data/rules.yaml`).
  - `connectMQTT(cfg *Config, onMsg func(topic string, payload []byte)) (mqtt.Client, error)`
- **Cài đặt paho:**
  - `SetClientID("hubd-" + 6 ký tự hex ngẫu nhiên)`, để hai client (kể cả trong test) không đá nhau khỏi broker;
  - `SetAutoReconnect(true)`, `SetConnectRetry(true)`;
  - `SetOnConnectHandler`: subscribe lại `cfg.Topics()` ở QoS 1 sau **mỗi lần** kết nối;
  - publish lệnh ở QoS 1, retained = false.

**Vòng lặp trong `main`:**
- `loop := make(chan func(), 256)` và `do := func(f func()) { done := make(chan struct{}); loop <- func() { f(); close(done) }; <-done }`.
- Một goroutine duy nhất chạy `for f := range loop { f() }`.
- Callback MQTT gửi `func() { hub.OnMessage(time.Now(), topic, payload) }` vào loop.
- **Ticker 1 s:** `hub.Tick(now)`.
- **Mỗi đêm 03:00:** `hist.Compact(now)`, có lỗi thì ghi log.
- **SIGHUP:** gọi `LoadConfig`.
  - Lỗi: log `reload rejected: <err>` và giữ cấu hình cũ.
  - Thành công: `do(hub.Reload(cfg))`, unsubscribe các topic cũ không còn dùng, subscribe các topic mới.
- **SIGTERM/SIGINT:** `srv.Shutdown`, ngắt MQTT, đóng DB.

**Khởi tạo:**
1. `os.MkdirAll(cfg.DataDir)`.
2. `OpenDB(DataDir + "/hubd.db")`.
3. Chọn sender: `TelegramSender` nếu có `Telegram.Token`, ngược lại `LogSender`.
4. Tạo HTTP server: `http.Server{Addr: cfg.HTTP.Listen, Handler: NewWeb(..., StaticFS())}`.

**Triển khai:**
- `deploy/hubd.service`:
  - `ExecStart=/data/bin/hubd -config /data/config.yaml -rules /data/rules.yaml`
  - `ExecReload=/bin/kill -HUP $MAINPID`
  - `Restart=always`, `RestartSec=2`
  - `User=hubd`, `AmbientCapabilities=CAP_NET_BIND_SERVICE`
  - `After=network-online.target mosquitto.service`
- `deploy/deploy.sh HOST`:
  1. build amd64;
  2. `scp` file lên `/data/bin/hubd.new`;
  3. qua ssh: `cp hubd hubd.prev && mv hubd.new hubd && systemctl restart hubd`.

- [ ] **Bước 1: Viết test tích hợp (chạy sẽ đỏ)** trong `mqtt_integration_test.go`, chỉ chạy khi có biến môi trường `HUBD_MQTT`

```go
func TestMQTTIntegration(t *testing.T) {
	broker := os.Getenv("HUBD_MQTT")
	if broker == "" {
		t.Skip("đặt HUBD_MQTT=tcp://127.0.0.1:1883 để chạy")
	}
	cfg := loadTestConfig(t)
	cfg.MQTT.Broker = broker
	cfg.Rules = []Rule{{ID: "t", When: Cond{Entity: "phongkhach.co2", Above: f64(1000)}, Then: []Action{{Set: "quat_hut_pk", To: "on"}}}}
	got := make(chan string, 1)
	spy, err := connectMQTT(&Config{MQTT: cfg.MQTT}, func(topic string, p []byte) {
		if topic == "obk-quat/1/set" {
			got <- string(p)
		}
	})
	if err != nil {
		t.Fatal(err)
	}
	spy.Subscribe("obk-quat/1/set", 1, nil).Wait()
	db := openTestDB(t)
	hist, _ := NewHistory(db)
	notif, _ := NewNotifier(db, LogSender)
	var hub *Hub
	c, err := connectMQTT(cfg, func(topic string, p []byte) { hub.OnMessage(time.Now(), topic, p) })
	if err != nil {
		t.Fatal(err)
	}
	hub = NewHub(cfg, hist, notif, func(topic, p string) error { return c.Publish(topic, 1, false, p).Error() })
	time.Sleep(200 * time.Millisecond)
	c.Publish("node-pk/sensor/co2/state", 1, false, "1500").Wait()
	select {
	case p := <-got:
		if p != "1" {
			t.Fatalf("payload %q", p)
		}
	case <-time.After(3 * time.Second):
		t.Fatal("không thấy lệnh trong 3 s")
	}
}
```

Gán `hub` sau `connectMQTT` là chấp nhận được trong test: chưa có message nào đến trước khi publish.
